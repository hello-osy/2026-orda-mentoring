# 트랙 출처와 구현 범위

- 입력: `2026 국민대 LIMO 트랙 도면.zip` 안의 `2026Track 도면 시트1.dxf`, `2026Track.png`, `2026Track 도면.pdf` (2026-10-19).
- 원본 DXF와 PNG는 `src/orda_sim/assets/`에 보존했다. `cad_paths.json`은 DXF `Visible` 레이어의 LINE 702개, SPLINE 218개, ARC 60개를 읽어 만든 좌표다. 곡선은 DXF 0.025 단위(실제 0.75mm) 오차로 표본화했다. 추출 절차는 `src/materials/rebuild_cad.py`에 보존했다.
- DXF는 mm로 선언되었지만 도면 좌표 자체는 1:30 축척이다. 외곽 범위 `(128.493923,121.986082)`–`(461.827256,321.986082)`를 실제 **10×6m**에 맞춰 `실제 m = (DXF 좌표 - 좌하단 원점) × 0.03`으로 환산했다. 외곽/갈림길/주차선/지그재그/횡단보도는 이 좌표에서 생성한다.
- 로봇 좌표: +X 전방, +Y 왼쪽, +Z 위. 세계 원점은 매트 좌하단이다. 차량 원점은 뒷바퀴 축의 지면 투영점이고 앞바퀴는 `robot.wheelbase` 위치다. 모델 외형·질량·마찰은 교육용 근사값이다.
- CAD 선의 둘레를 래스터화하고 좁은 도색 영역 내부를 채운다. PNG의 노란 CAD 강조색은 실제 차선 검출 연습을 위해 흰색으로 표시한다. 그림의 작은 문자/도색 테두리는 렌더링 해상도에 따라 달라진다.
- 이동 가능한 시설물의 정확한 위치·표지판 최종 도안·라바콘 개수는 첨부 자료로 확정할 수 없다. YAML `scene`의 위치와 자체 제작 표지판 도안은 **연습용 가정**이다. 정차 LIMO는 규정의 7대와 주차 양옆 2대를 반영했다. 라바콘은 고정 벽이 아닌 움직일 수 있는 물체다.
- 신호등 3색, 갈림길 좌/우, 광고판 3프레임은 런타임에 판면 모델을 전환한다. 광고판은 실제 광고 동영상 대신 움직이는 색상·문자 화면이다. 객체 정답 라벨은 Gazebo `visible_2d` 카메라로 판면의 보이는 영역에서 생성한다. 게시물 지주는 라벨에서 제외한다.
- 규정 우선순위: 2026-10-08 규정집의 **8종/100점**과 속도·정지 기준을 우선하고, 2026-09-28 미션 초안의 9개 분류와 충돌하는 부분은 최신 규정집을 따른다.
- 규정의 “한 바퀴” 설명과 달리 CAD 노면은 출발 직선에서 우측→하단→좌측→상부 안쪽 주차로 이어지며 출발선으로 연결되는 선이 없다. 도면에 없는 연결 차선을 임의로 추가하지 않았다.

Gazebo 공식 구현 근거: [AckermannSteering](https://gazebosim.org/api/sim/8/classgz_1_1sim_1_1systems_1_1AckermannSteering.html), 설치 예제 `/usr/share/gz/gz-sim8/worlds/ackermann_steering.sdf`, `/usr/share/gz/gz-sim8/worlds/boundingbox_camera.sdf`.

주차 시퀀스 진입 자세를 맞추기 위해 `scene.parking_reference`에 **연습용 기준 테이프**를 추가했다(기본 X=7.4m, 동쪽으로 주행하는 주차 접근 차로). 원본 CAD에는 없는 추가물이며 YAML에서 끌 수 있다. `parking_pose` 표지판은 동쪽 접근에서 보이도록 차로 밖에 배치했다. 주차 시퀀스는 휠베이스와 조향각으로 구한 초기값에서 시작해 아래의 실제 물리 시험으로 보정했다.

현재 ARM Mesa 환경은 사용 불가능한 DRM 장치를 첫 번째 EGL 장치로 보고한다. `environment.egl_software_only`를 켜면 프로젝트 내 C 필터를 해당 Gazebo 프로세스에만 적용해 llvmpipe 장치를 선택한다. 시스템 라이브러리를 교체하지 않으며 일반 GPU 환경에서는 끌 수 있다. `src/runtime_support/egl_software.c`에 구현·컴파일 방법이 있다.

카메라에서 접근·정지 후에도 판독할 수 있도록 갈림길 표지판은 섬 내부, 신호등은 정지선 뒤쪽에 배치했다. 갈림길 방향은 실행 시작 후 한 번 선택하여 해당 시도 동안 유지한다. 이 시설물 좌표는 원본 CAD에 없는 연습 배치이며 `scene`에서 바꿀 수 있다.

주차의 시간 기반 동작은 실제 Gazebo 물리로 보정했다. 정규화된 뒤축 좌표 `(7.05, 4.84, yaw=0)`에서 초기 이론 시퀀스는 한 모서리가 1mm 벗어났다. 전진 2.1초→후진 우조향 6.65초→직진 후진 3.0초→정지 3.2초로 바꾼 후 실제 네 모서리 최소 여유 10.47cm로 들어갔다. 허용 정렬 오차의 두 경계 자세(위치 ±2.5cm/±3.5cm, 방향 ±0.09rad)도 각각 3.72cm/5.80cm 여유로 통과했다. 이 검증은 **정렬 이후의 시간 기반 동작만** 대상으로 하며 YOLO 인식부터 주차 완료까지의 전체 미션 검증과 구분한다. 원자료는 `src/artifacts/evaluations/parking_calibration_summary.json`과 각 trial 폴더에 있다.

이어 실제 RGB·라이다·차륜 오도메트리로 주차 정렬까지 시험했다. P 표지판의 인식 트리거만 주입하고 절대 위치는 평가에만 사용했다. `(6.4,4.84,+0.05rad)`에서 9.40초 정렬 후 주차 최소 여유 11.96cm로 통과했다. 더 이른 `(5.8,4.84,-0.05rad)`는 기존 14초 제한으로 정렬 중 멈췄고, 제한을 24초로 늘린 재시험에서 16.90초 정렬 후 최소 여유 10.87cm로 통과했다. 원자료와 실패 사례는 `src/artifacts/evaluations/parking_alignment_01..03/`, 재현 코드는 `src/tests/parking_alignment_harness.py`에 있다. 이 결과는 **YOLO 인식을 포함한 전체 주차 미션 성공을 뜻하지 않는다.**

후속 후반 구간 독립 시험에서는 최종 학습 YOLO를 실제로 사용해 신호등 정지→녹색 출발→P 인식→카메라 정렬→주차까지 연결했다. `(1.8,4.84)`에서 출발해 정지선 3.65cm 앞에서 10.712초 정지한 뒤 녹색에서 통과했고, 주차 네 모서리 최소 여유 10.71cm·정차 3.09초로 종료했다. 신호 검출 최소 면적 `.025`, 신호 주기 `20/10/2초`, RTF `.6`의 임시 설정을 사용했으며 원본 선이나 시설 위치는 바꾸지 않았다. 이 시험은 **후반 구간 검증이며 전체 코스 완주가 아니다.** 앞선 반복에서 경고선 오인, 긴 정지 중 선 메모리 만료, 두 Gazebo 동시 실행 시 영상 지연을 확인했고 실패 자료도 보존했다. 최종 근거는 `src/artifacts/evaluations/traffic_parking_segment/run_20261028_003830_131399/audit.json`이다.

최종 전체 코스 검증은 기본 왼쪽 경로1회와 수정 구간 재현·카메라 중단 주차 시험으로 마무리했다. 우측 전체 완주 기록은 이전 버전 결과다. 최종 수치·궤적·설정과 각 검증 범위는 [validation.md](validation.md)에 기록했다.
